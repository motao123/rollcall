## 0. 结论

1. **定位不同，先划清不追的部分。** KPanel 是"面板 + 集群 + 远程运维"，四家竞品是探针；Rollcall 是"监控 + 资产台账"，且 **Agent 只读、无 exec、无监听**。远程终端、文件管理、批量命令这三项是 KPanel 的强项，也是它自己承认的风险源（页面引用哪吒 #1210：面板失守后经该链路批量下发木马）。Rollcall 不做，且这正是要守住的差异。
2. **我们领先的地方比想象中多。** 公开页历史图表、通知渠道数量、流量计费口径（4 种）、审计日志、发行签名、加密备份、主题包，KPanel 在这一页里把其中多项标成自己的缺口（F4/F6/F7/F9）。
3. **真正该补的是三件事**：① 公开页**默认对全网开放**（实测匿名 200 且能看到节点名），这是安全事故级别的默认值；② 探测只能从中心发起、且**不支持 ICMP**，这是与四家竞品最大的功能差距；③ 上报链路只有**静态令牌**、无签名无时间戳，明文 HTTP 下可被抓包重放。
4. 剩下的是"人无我有、人有我优"的补全（IP 变更通知、登录通知、流量手动校正、离线合并），单项都很小。

## 2. 需新增的功能

### P0（安全与默认值，建议 1–2 周内做完）

**P0-1 公开页加"总开关 + 访问令牌 + 逐台隐藏 + 公开备注"**
- 现状：`GET /status` 与 `/api/status` 匿名可访问，**默认暴露全部节点名/分组/在线状态**。生产实测：`curl /status` → 200，`/api/status` 直接列出全部节点名（示例：`node-a / node-b / node-c`）。
- 理由：监控面板通常挂在公网 IP 上（我们就是 `0.0.0.0:19080` 明文 HTTP），节点名往往等于"服务商 + 地区"，等于泄露资产清单；竞品四家全都有开关，KPanel 更是**默认关闭 + 随机令牌可重置**。
- 做法：`StatusPage` 增加 `enabled`、`token`（可选，命中才放行，支持 `?t=` 与 Cookie）、`hiddenNodes []string`、`publicNotes map[string]string`；`handleStatusPage` 与 `/api/status` 统一走同一个可见性过滤器；公开备注要过 `sanitize`，且**不得**复用内部 `Note` 字段。
- 成本：小（1–2 天）。位置：`internal/web/statuspage.go`、`internal/web/statuspub.go`、`internal/model/model.go`。

**P0-2 上报链路加时间戳 + 签名（或至少时钟偏差告警）**
- 现状：`X-Node-Token` 静态令牌，无时间戳、无签名；链路是明文 HTTP。任何能抓包的人可无限重放，伪造指标触发误告警（我们的告警会发到 Telegram/企微）。
- 理由：KPanel 用"每台独立密钥 + 签名 + Noise 防重放"；我们虽然 Agent 只读（伪造指标危害有限），但**误报告警**本身就是事故。
- 做法：最小可用方案是 `X-Node-Ts` + `HMAC-SHA256(token, ts|body)`，服务端允许 ±90s 窗口并记最近 N 个 nonce；同时把 `ts` 与本地时间差记进节点（现在的 `lastIP` 旁边加 `clockSkew`），面板能提示"该节点时钟偏差 N 秒"。
- 成本：中（2–3 天，含灰度：先允许无签名，配置开关后才强制）。位置：`cmd/agent`、`internal/web/web.go`、`internal/store`。

**P0-3 三个"小通知"一次做完：IP 变更、后台登录、多台离线合并**
- IP 变更：`lastIP` 已经在存，变化时比对旧值推送即可（半天）。
- 后台登录：`auth.go:147` 已经拿到 user/ip，直接进 outbox（半天）。
- 离线合并：一轮评估里的离线/恢复各合并成一条，避免机房整体掉线刷屏（1 天）。
- 理由：三项都是竞品里"人无我有"的小优势，成本极低，且能显著降低运维噪音。

**P0-4 本周期流量手动校正**
- 现状：周期基线由服务端按 `resetDay` 推算，无法录入"服务商面板上已经用掉的量"，对账永远差一截。
- 理由：KPanel 把这条列进"建议跟进 F6"且自己也没做；CF-Server-Monitor 与 monitor 都有。对有配额的真金白银场景是刚需。
- 做法：`POST /api/admin/nodes/{id}/traffic-adjust`，写入本期基准偏移，清掉"不完整"标记，写审计。
- 成本：小（1 天）。

### P1（对标功能）

**P1-1 ICMP 探测 + 探测项可指定执行位置**
- 现状：`internal/probe/probe.go` 只支持 `http/https` 与 `tcp`，`probe_test` 里还明确断言 `icmp` 非法；所有探测**只在控制端执行**（`/api/services/compare` 的 `note` 里也写明了）。
- 理由：四家竞品都能在节点侧探测，我们只能测"控制端到目标"，对"节点到目标"的线路质量一无所知——这正是监控最常被问的问题。ICMP 相对 HTTP 更接近线路真实延迟，且是最低成本的补法（先做中心侧 ICMP，再做下放）。
- 做法：① `probe` 增加 `icmp`（raw socket 或 `ping` 二选一，容器环境要能降级到 tcp 握手）；② 长期：`Service` 增加 `vantage`（`control` / `node:<id>`），Agent 侧新增探测协程与上报字段，中心聚合。②是"大"成本，建议拆两个版本做。
- 成本：①小（1 天）②大（1–2 周）。

**P1-2 统计网卡可指定 + 网卡集合变化重建基线**
- 现状：`readNetDev` 自动跳过虚拟网卡（veth/docker/br-/cni/cali），并处理 bond 从属，但不能指定或排除；累计值来自各网卡求和。
- 理由：默认路由切换（WARP、多 WAN 故障切换）会让累计值整体跳变，跳高的部分会被当成真实流量记进本月配额。KPanel 页面末尾的"附带发现"就是同一类问题。
- 做法：`agent.json` 加 `includeNICs`/`excludeNICs`；上报带网卡集合指纹，集合变化时中心重建基线并标记该周期不完整。
- 成本：中。

**P1-3 主机 SSH 登录告警**
- 现状：采集里没有 utmp/session 解析，无此能力（KPanel 独有）。
- 理由：VPS 被爆破/被盗登的第一信号就是登录记录；竞品里只有 KPanel 做，做了就是差异点。
- 做法：Agent 读 `/var/run/utmp`（或 `who`）取当前会话，中心对比上一轮差异后推送；只报"新增来源 IP + 用户"，不报完整会话内容。
- 成本：中（解析 + 去抖 + 通知模板）。

**P1-4 只读 MCP server**
- 理由：KPanel 已经"API + MCP"，这是 2026 年的接口形态；我们的作用域令牌天然适合做只读 MCP（`/api/overview`、`/api/nodes`、`/api/assets`），且**不违反 Agent 只读边界**。
- 成本：中（一个 `cmd/mcp` + 工具定义）。

**P1-5 后台登录加固补齐**：Passkey（WebAuthn）与"安全入口"（自定义路径）。KPanel 有，我们的 TOTP 已经很稳，Passkey 属加分项。成本：中。

**P1-6 容器级指标 / GPU / 温度**：按需。VPS 场景价值中等；家用设备（飞牛/群晖）才有明显收益，与 KPanel 的判断一致。

## 4. 样式与视觉

KPanel 那一页本身就很值得偷师：**能力矩阵用 ●◐○ 三态 + 分组 sticky 表头 + 行内 F 编号锚点 + 顶部统计条（44 项 / 落后 17 / 领先 11）**，信息密度高但不吵。对应到 Rollcall：

| 编号 | 位置 | 现状 | 建议 | 理由 |
|---|---|---|---|---|
| S1 | 面板「设置 → 关于」 | 只有版本号与构建信息 | 做一张"能力矩阵"：维度（采集/探测/通知/公开页/安全）× 状态 ●◐○，链接到对应设置页 | 借对方手法把"我们有什么"讲清楚；也让用户知道该去哪个页面打开 |
| S2 | 节点表格 | 列多，窄屏靠横向滚动 | 首列（名称）冻结 + 表头 sticky + 滚动阴影 | 1280 以下现在要滚到右边就看不到是哪台机器 |
| S3 | 公开页卡片 | 无数据时显示 `—` | 用统一的"数据不足"空态（灰 + 说明文字），并对 >5 分钟未上报的卡片加时间戳徽标 | 现在空值和"真的 0"在视觉上不可区分 |
| S4 | 主题包 | 只有文档示例，无现成皮肤 | 随包发布 2 个官方示例（`themes/dark-compact`、`themes/light-docs`） | 降低主题包门槛，也是对外展示 |
| S5 | 状态指示 | `dot + 文字`（在线/延迟/离线） | 表格里用 `dot + 短标签`，hover 出完整说明；详情页保留完整文字 | 与 ●◐○ 同思路，省宽度 |
| S6 | 面板密度 | 单行约 40 px（`padding: 10px 14px`） | 加"紧凑模式"开关（28–32 px），与主题的 `compact` 字段打通 | 13 台还好，40 台一屏看不完 |
| S7 | 数字列 | 已实现：`td.num` 有 `tabular-nums` + 右对齐 | 保持，并在公开页卡片数值上同样应用 | 刷新时数字不抖动，是表格可读性的地基 |
| S8 | 公开页 KPI | 卡片自动换行（v1.14 已做） | 给"可用率/延迟"加 7 天 sparkline 缩略 | 竞品公开页大多只有当前值，这里是我们的差异点 |

## 5. 不跟进（含理由）

| 能力 | 谁在做 | 不做的理由 |
|---|---|---|
| Web 终端 / 文件管理 / 批量命令 | KPanel、哪吒、Komari | 与 Rollcall 的核心边界冲突：我们的 Agent **没有 `os/exec`、没有 `net.Listen`**，服务端也不下发指令。攻击面从"任意 RCE"降到"伪造指标"。KPanel 页面自己引用了哪吒 #1210（面板失守 → 经该链路批量下发木马），这正是要避免的形态 |
| 采集间隔降到 3 秒 | 哪吒、Komari | 30 秒是成本与稳定性的平衡；真有需求时做"打开详情页临时提频"，而不是全局提速 |
| 多用户与权限分级 | 哪吒 | 单人运维场景收益小、权限模型改动大（与 KPanel 的判断一致） |
| 同源主题/插件市场 | Komari | 我们的主题包已经在同源执行 `status.js`，再开放市场会扩大攻击面；先考虑把主题挪进 iframe（见 P0 之后） |
| 网站/Docker/应用托管 | KPanel | 定位不同：Rollcall 不做托管，只做"看得见、算得清" |

- Rollcall 现状：逐条在仓库核对（`internal/probe`、`internal/collect`、`internal/store`、`internal/web`、`internal/notify`、`internal/schedule`），并在生产实例（示例 IP `203.0.113.10`）上实测了公开页匿名可访问。
