## 二、可借鉴点（按投入产出排序）

### P0 — 成熟实现，直接可搬

#### 1. 指标降采样阶梯 + t-digest 分位数
- **来源**：`Argus/server/internal/metric/rollup.go`、`Argus/server/internal/tdigest/tdigest.go`
- **对方方案**：分钟表 → 5 分钟表（Gran5m=300）→ 小时表（GranHour=3600）三级聚合 + 过期清理；
  分位数用 Dunning–Ertl t-digest（`DefaultCompression=30`，质心可 **Merge**，因此降采样不丢尾部精度）。
- **Rollcall 现状**：`Ring[Metrics]` 固定 2880 点（24h@30s），长区间由「桶内平均」聚合；
  服务延迟历史同样只有均值。**看不出尖峰与雪崩尾部**。
- **落点**：新建 `internal/metric/tdigest.go` + 在 `Series` 聚合路径补 p50/p95/p99；
  `ServiceSample.Latency` 历史复用同一摘要。注意需同时升 `SnapshotSchemaVersion`（现为 5）。
- **场景**：容量判断看 CPU **p95** 而非均值（均值 30% 但 p95 90% 就是过载）；
  探测延迟 SLA 看 p99；图表增加「p95 线」。
- **成本**：中（约 400–500 行 + 序列化 + 回归）。

#### 2. Playwright `storageState` 复用登录态
- **来源**：`panelOps/h.js`
- **对方方案**：`chromium.launch({headless:false, slowMo:200})` + `storageState` 读写 `state.json`，
  登录一次后续复用；`try/catch` 内失败自动 `page.screenshot({path:"err.png"})`。
- **Rollcall 现状**：验证脚本（`scripts/cdp_*.js`）**每次重新登录取密码落盘** `rcpwd.txt`；
  失败只有 stderr，无现场截图。
- **落点**：`scripts/ui-auth.mjs` 统一封装（storageState → `.auth/state.json` 并加 .gitignore），
  所有 CDP 脚本改为 `withSession(fn)`，失败自动 `err-<route>.png`。
- **场景**：发版后 UI 回归、详情页/分页断言、截图存档。
- **成本**：低（半天）。**顺带消除密码落盘这个卫生问题。**

#### 3. WCAG 对比度自检进 CI
- **来源**：`github-trends-site/scripts/check-contrast.mjs`
- **对方方案**：纯函数实现 srgb→相对亮度→对比度，对 light/dark 两套 token 全组合断言 ≥ 阈值。
- **Rollcall 现状**：手写 CSS、深浅双主题、8 个语义色（且「使用率/可用率」配色方向相反），
  **无任何自动校验**；v1.35.1 就出过「公开页进度条透明」的配色事故。
- **落点**：`scripts/check-contrast.mjs` 解析 `style.css` 的 `:root` / `[data-theme=dark]` 变量，
  对 `--fg/--fg-2/--fg-3/--bg/--panel/--warn/--crit/--ok` 两两组合断言正文 ≥4.5、次要 ≥3；
  CI 加一步 `node scripts/check-contrast.mjs`。
- **场景**：主题包审核（`/opt/rollcall/data/themes`）、新增语义色时的回归。
- **成本**：低（算法现成，只需做 CSS 变量抽取）。

#### 4. 部署矩阵补齐（compose / nginx / env 模板）
- **来源**：`Argus/deploy/`（Dockerfile + docker-compose.yml + argus.env.example + nginx.conf + systemd + OpenRC）
- **Rollcall 现状**：有 `Dockerfile`，**无** compose、无 env 模板、无反代样例。
- **落点**：`deploy/docker-compose.yml`（挂 `/opt/rollcall/data` + `TZ` + 端口 19080）、
  `deploy/nginx.conf`（`proxy_buffering off` 保 SSE、`X-Forwarded-Proto`、WebSocket 无需）、
  `deploy/rollcall.env.example`。与现有 Caddy+ACME 生产形态并存。
- **场景**：新用户自托管；同一份文档覆盖 systemd / Docker / 反代三种路径。
- **成本**：低。

#### 5. 发版验收清单「证据化」
- **来源**：`Argus/docs/checklist.md`、`verification.md`
- **对方方案**：每步一张表，**每行都附证据**（命令、输出、截图路径、提交号），可复跑核对。
- **Rollcall 现状**：README 第十二章有历史验证表，但**不是可勾选的清单**，且散落在版本条目里。
- **落点**：`docs/release-checklist.md`：8/8 digest 表、`readyz`、CDP 断言、验签输出、
  Agent 版本分布、对比度检查——每项一行「命令 + 期望」。发版时复制成 `docs/verify-vX.Y.Z.md` 填证据。
- **场景**：每次发版的 DoD；换人接手时不必靠记忆。
- **成本**：低。

### P1 — 收益明确，需设计取舍

#### 6. ~~通知渠道敏感字段脱敏~~ —— **已实现，本项撤销（评估误判）**
- **原判断**：`GET /api/admin/settings` 原样返回渠道 url/token。
- **核实结果（2026-10-27 复核）**：**脱敏早已实现且带测试**——
  `notify.Config.Redacted()`（未知类型时「宁可将全部非空字段脱敏」）、
  `mask()`/`isMasked()`（阈值兼顾 11–20 字符串如QQ邮箱授权码）、
  POST 侧「还原脱敏占位符」+ `notifySaveMu` 串行锁防并发覆盖；
  测试见 `internal/notify/mask_test.go`、`plugin_test.go`。
- **误判原因**：我只 grep 了 `internal/notify/*.go` 与 `internal/web/notify*.go`，
  而实现分布在 `notify/notify.go`（Redacted）与 `web/web.go`（handleAdminSettings）。
- **教训**：横向评估的每条断言必须按「功能关键词」全仓 grep，不能按文件名猜位置。

#### 7. Agent 协议能力协商
- **来源**：`Argus/protocol/protocol.go`（`ProtocolVersion = "2"` + `CapabilityMetrics/Probe/Command/…`）
- **对方方案**：注册时声明能力集，服务端按能力决定下发与渲染，天然向前兼容。
- **Rollcall 现状**：靠纪律——「加附加信息用请求头、不加 JSON 字段」（因为 `Report` 是
  `DisallowUnknownFields`，加字段会让旧服务端整份 400，升级顺序被迫反转）。
- **落点**：上报头加 `X-Agent-Proto: 2` + `X-Agent-Caps: diskio,temp,nic`；服务端记录并按能力
  启用新图表。请求头方案对旧服务端无影响，与现有纪律一致。
- **场景**：将来加 SMART / GPU / 网卡分环 / 连接跟踪等可选采集。
- **成本**：中（协议小、但要测新旧混跑）。

#### 8. 后端分页 + 统一响应信封
- **来源**：`Argus/docs/standards.md`（`{success,data,pagination}` + 错误码表 + `offset/limit` 默认 50 上限 500）
- **Rollcall 现状**：`writeJSON`/`fail` 返回裸结构；**全部分页在前端**（v1.35.3 刚统一每页 10 条）。
  审计日志、告警记录、通知队列都是「服务端一次性返回最近 N 条」。
- **落点**：先只对**会无界增长**的三处加服务端分页：`/api/admin/audit`、`/api/admin/alerts/records`、
  `/api/admin/notify/jobs`。用 `?offset=&limit=`，响应附 `page{total}`；前端表格改为「取当前页」。
  破坏性变更走新的 `/api/admin/audit/page` 或加 `Accept: v2`，避免动老路由。
- **场景**：机群上百台、审计保留 90 天后的实际体感。
- **成本**：中。

#### 9. 线上安全头 / TLS 审计脚本化
- **来源**：`bxait-pentest/recon/headers_audit.py`
- **对方方案**：对目标清单逐项检查缺失/配置错误的安全头 + TLS 信息，输出 JSON 报告。
- **Rollcall 现状**：CSP / HSTS / 安全头都在代码里正确设置，但**没有线上回归**；
  v1.35.2 从内置 TLS 切到 Caddy+ACME 时，这类配置就靠人工看。
- **落点**：`scripts/audit-headers.py`（或 .mjs）对 `https://status.endgo.top` 断言：
  `Content-Security-Policy` 含 `script-src 'self'`、`Strict-Transport-Security` 存在、
  `X-Content-Type-Options: nosniff`、`Referrer-Policy`、证书剩余天数 ≥14；
  失败非零退出，可挂到自动化。
- **场景**：反代/证书配置变更后的回归；开源用户的部署自检。
- **成本**：低。

### P2 — 长期/可选

#### 10. 公开页 SEO 与社交卡片
- **来源**：`github-trends-site`（`scripts/prerender.mjs` + `check-seo.mjs` + `manifest.webmanifest`）
- **现状**：Rollcall 公开页是 SPA（`status.js` 客户端渲染），搜索引擎与社交预览拿不到内容；
  分享链接无卡片图。
- **落点**：`/status` 首屏由服务端注入 `og:title/og:description/og:image` 与静态摘要
  （节点数、可用率、当前告警数），SPA 只接管交互。**不做全站预渲染**（收益/成本不划算）。
- **场景**：把这页当「服务可信度」对外展示时。
- **成本**：中。

#### 11. 自定义定时任务（cron）
- **来源**：`Argus`（5 段 cron + 执行结果截断 ≤2KB）
- **现状**：Rollcall 只有内置探测与内置自动备份，无用户自定义任务。
- **风险**：与本项目「服务端不下发指令」的边界天然冲突——若只在**控制端**跑（备份、导出、
  清理），不涉 Agent，则边界仍成立。
- **结论**：**暂不做**。现有内置能力（备份/清理/到期提醒）已覆盖高频需求。

#### 12. i18n / GeoIP / 地图
- **来源**：i18n ← CF-Server-Monitor 分析（三语）；GeoIP/地图 ← Argus、CF
- **判断**：i18n 成本高（前端字符串全量抽取），仅在确定开源面向国际时做；
  GeoIP 需引 MaxMind 库，**破坏零依赖**，13 台规模用不上地图。两者均列**低优先**。

## 三、明确不借鉴（保住护城河）

| 对方能力 | 不借鉴理由 |
|---|---|
| 远程命令 / 网页终端 / 文件管理（Argus `exec`/`terminal`/`files`、nezha 均有） | **Rollcall 的核心边界**：Agent 只读、单向、不监听、不执行 → 攻击面从任意 RCE 降为「只能伪造指标」。用功能换这条，不划算 |
| SQLite / GORM（Argus） | 无库是部署优势：单文件 gzip 快照，备份=复制一个目录。只借**降采样思想**（见 P0-1），不借 DB |
| React + Vite + Tailwind 构建链（Argus） | 无构建链意味着改一行 CSS 即生效、`go:embed` 产物可逐字节复现；构建链会让「本地=CI」的 digest 一致性变复杂 |
| JWT 会话（Argus / CF） | 现有面板会话 + TOTP + 撤销表已覆盖同等能力，迁移收益为零 |

## 四、Rollcall 优于各方、可反向输出

| 能力 | 说明 | 对方缺口 |
|---|---|---|
| 发行签名链 | `rollsign sign-release` + 生产机端到端验签 + `.sig` 随 Release 发布 | Argus / nezha / komari **均无**制品签名 |
| 上报签名 | HMAC(`v1\nts\nnonce\nsha256(body)`) + ±90s 窗口 + nonce 去重 | Argus 仅共享 secret，无请求级签名与重放防护 |
| Agent 证书指纹固定 | `serverCertPin` = 叶证书 DER SHA-256，指纹优先于 skipVerify，格式错即启动失败 | 各家普遍 `tlsSkipVerify` 或自签即跳过 |
| 公开页门槛 | `enabled/token/hiddenNodes/publicNotes` + 失败限速（30 次/分）+ 未开放一律 404 | nezha 公开页无令牌门槛与枚举防护 |
| 单文件快照 | gzip JSON + 环形缓冲，**无 DB**，快照 schema 版本化（现 5） | 全部依赖 SQLite/D1，迁移与膨胀是长期负担 |
| CSP 纪律 | `script-src 'self'`，JS 必须外部文件，内联 SVG 仅作装饰 | 普遍内联脚本，XSS 面更大 |
