# 安全审计报告（2026-10-26）

审计对象：Rollcall 全栈（server / agent / themepack / netguard / 部署层 Caddy+ACME）。
方法：govulncheck 依赖扫描（go1.24.0 与 go1.26.2 双基线）、路由权限矩阵逐项核对、
认证/会话/公开面/上报链/SSRF/文件处理精读、生产环境配置实测、CDP 响应头实测。

> 结论先行：**未发现可直接远程利用的严重漏洞**。发现 2 项中危（标准库漏洞面、
> 安装命令注入卫生）、2 项低危（公开 token 无限速、反代下公开 Cookie 缺 Secure），
> 其余为加固建议。整体安全设计在同类自托管项目中属于高水准，详见文末正面清单。

---

## 一、中危

### M1 Go 标准库 48 个已知漏洞被调用（工具链过旧）

- **位置**：生产二进制的构建工具链 `go1.24.0`（govulncheck 实测：48 个标准库漏洞
  被代码实际调用；若用 go1.26.2 基线也有 23 个）
- **原因**：项目钉 `GOTOOLCHAIN=go1.24.0`（为保证构建可复现），但 1.24.0 的
  `net/http`、`net/url`、`crypto/*` 存在大量后续修复的标准库漏洞
- **可利用性**（择要，全部对公开面真实可达）：
  - 请求走私：`net/http` 接受非法 chunked 数据 / CONNECT 响应后连接不同步
    —— Caddy 反代与 Go 后端对请求边界的理解可能分歧
  - DoS：HTTP/2 Trailer 头内存耗尽、HTTP/2 流控双重退款、Cookie 解析内存耗尽
    （登录页无需认证即可投递 Cookie）、查询参数解析内存耗尽
  - 其它：跨源重定向未清除敏感头、x509/tls 校验缺陷（主要影响 Agent 侧作为客户端）
- **修复建议**：升级构建工具链到 1.24.x 最新 patch（或直接 1.26.3+），同步修改
  Makefile / CI workflow / 构建文档中所有 `go1.24.0` 锚点，重新构建发布
  （digest 变化属预期，走正常发版流程）。标准库漏洞会持续累积，建议把
  「工具链跟随最新 patch」列入例行维护，而不是长期钉死 minor 版本。

### M2 「节点接入命令」可被 panelLink 注入 shell 命令替换

- **位置**：`internal/web/panellink.go` 的 `normalizePanelLink` +
  `internal/web/agent_install.go:723` 的 `agentInstallCommand`
- **原因**：`url.Parse` 放行 Host 中的 `;`、`$`、`()`（实测
  `https://a.com$(id)` → Host=`a.com$(id)`），normalize 后原样重组；
  接入命令用 `fmt.Sprintf` 直接拼接，**无 shell 引号包裹**：
  `curl -fsSL <base>/agent/install.sh | sh -s -- <base> <nodeID> <token>`
- **利用链**：需要管理员权限设置恶意 panelLink（或管理员自己粘贴了含特殊
  字符的 URL）→ 批量导入响应 / 接入命令页展示该命令 → 管理员复制到目标
  服务器执行 → `$()` 命令替换在**目标服务器**上触发
- **影响**：命令注入卫生缺陷（前置条件为 admin 权限，非远程可达），但接入
  命令本来就要在生产服务器上执行，值得认真对待
- **修复建议**（两层都做）：
  1. `normalizePanelLink` 对重组前的 `u.Host` 做字符白名单
     （`[A-Za-z0-9.:\-\[\]]`，覆盖域名/IPv4/IPv6 括号/端口）；
  2. `agentInstallCommand` 的三个插值参数一律单引号包裹
     （`'%s'`，并把值中的 `'` 替换为 `'\''`）。

## 二、低危

### L1 公开状态页访问令牌校验无限速

- **位置**：`internal/web/statusgate.go` `publicTokenOK`（注释明确"不做限速"）
- **原因**：令牌是「知道链接才进得来」模型，但校验失败无任何限速与审计，
  弱令牌可被高速在线枚举（常量时间比较不防在线爆破）
- **修复建议**：管理端保存 token 时强制 ≥16 位随机串（当前仅 UI 提示）；
  对 `?t=` 校验失败的请求加一个独立的慢速失败限速桶（如每 IP 每分钟 30 次），
  与鉴权限速分桶互不挤占

### L2 经反向代理时公开页 Cookie 缺 `Secure` 属性

- **位置**：`internal/web/statusgate.go` 种 Cookie 处：`Secure: r.TLS != nil`
- **原因**：TLS 由 Caddy 终止，Go 进程看到的连接是明文回环，`r.TLS == nil`，
  因此 `rollcall_st` Cookie 永远不带 Secure；而**会话** Cookie 用的是
  `s.requestIsHTTPS(r)`（信任可信代理的 X-Forwarded-Proto），两处不一致。
  结果：HTTPS 部署下公开页 Cookie 可能经明文 HTTP 泄露
- **修复建议**：改为 `Secure: s.requestIsHTTPS(r)`，与会话 Cookie 一致

## 三、备注（设计取舍，暂不需修）

- **nonce 去重表（4096 上限）被打满时整体清空**（reportsig.go）：攻击者需先持有
  任一节点 token 才能灌表，而持有 token 本就等于可自由伪造上报内容，清空去重表
  不构成新增能力。留意：若未来引入"只读泄漏 token"的路径，此处需改为按节点分表
- **nonce 表仅存内存**（重启丢失）：±90 秒重放窗口在重启后重开。利用它需要
  重启前刚捕获的合法签名请求，收益极低；注释已说明取舍，可接受
- **`/api/theme` 公开**：仅返回当前主题名（非敏感配置），可保持

## 四、确认良好的安全实践（对照组）

| 领域 | 实测结论 |
|---|---|
| 依赖供应链 | **go.mod 零第三方依赖**，纯标准库，无投毒/typosquatting 面 |
| 密码存储 | PBKDF2-SHA256 **600k 迭代**（OWASP 对齐），格式化落盘可平滑升代数 |
| 比较侧信道 | 所有令牌/指纹/会话校验全部 `subtle.ConstantTimeCompare` / `hmac.Equal` |
| 会话 | HMAC 签名 + 版本失效（改密即踢）、HttpOnly + SameSite=Strict + Secure（随可信代理判定） |
| CSRF | 登录仅收 JSON + 管理写操作要求 X-Requested-With + SameSite=Strict |
| TOTP | 时间步**原子消费**（同一码只能登录一次，±1 窗口不可重放），与账号操作共用互斥锁 |
| 爆破防护 | 401 分桶计数 + 封禁 + 成功清零的正确实现（含"过期会话 401 误伤"的回归测试） |
| 输入解析 | 全部 JSON 端点 `DisallowUnknownFields` + `MaxBytesReader` + 多余内容拒绝 |
| 上报完整性 | HMAC(token, v1‖ts‖nonce‖sha256(body))、±90s 窗口、nonce 去重、64KB 上限 |
| SSRF | netguard 解析后逐 IP 校验 + **DialContext 连接时二次校验**（防 DNS 重绑定），覆盖 ISATAP/CGNAT/回环 |
| 路径安全 | 主题资产文件名白名单（仅 style.css/status.js）、目录名正则、`Lstat` 拒绝符号链接 |
| CSV 导出 | `csvSafe` 公式注入防护（`= + - @ Tab CR` 前缀加 `'`），BOM 处理正确 |
| 响应头 | 严格 CSP（script-src 'self'）、HSTS、nosniff、frame-ancestors 'none'、API no-store（经 Caddy 透传实测生效） |
| 部署 | 数据目录 0600/750、admin.token/session.key 0600、Caddy admin 仅回环、公网仅 443 单入口、证书 ACME 自动续期 |
| Agent 边界 | 依赖树**无 `os/exec`**、代码无 `net.Listen`/`exec.Command`（只读、单向、不执行） |
| 权限模型 | 四级鉴权矩阵启动时校验（未分类/重复/缺 handler 直接拒绝启动），admin 写操作另有同源与当前密码要求 |
