三、部署步骤（可复现）
--------------------------------------------------------------------------------

【步骤 1】本地交叉编译（静态链接，无 CGO）
  cd probe
  GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" \
      -o dist/probe-server-linux-amd64 ./cmd/server
  GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" \
      -o dist/probe-agent-linux-amd64 ./cmd/agent

  产物校验（部署时已核对一致性）：
    probe-server  sha256 = 1b0c12fd2966e5820636a1366ffccd551af0150eea7332f88aaf72732a073ad1
    probe-agent   sha256 = 993400fcab6c2d1c31a1c71babbcdabe02844aaa74078c141f217969693480ed

【步骤 2】创建目录与系统用户
  mkdir -p /opt/probe/data /etc/probe
  useradd --system --shell /usr/sbin/nologin --home-dir /opt/probe probe
  chown -R probe:probe /opt/probe
  chmod 0750 /opt/probe/data

  → 独立系统用户，无登录 shell，最小权限

【步骤 3】安装二进制
  install -m 0755 probe-server-linux-amd64 /usr/local/bin/probe-server
  install -m 0755 probe-agent-linux-amd64  /usr/local/bin/probe-agent

【步骤 4】安装控制端 systemd 单元
  /etc/systemd/system/probe-server.service
    User=probe  Group=probe
    ExecStart=/usr/local/bin/probe-server -addr 127.0.0.1:19080 -data /opt/probe/data
    Restart=always
    NoNewPrivileges=true  ProtectSystem=strict  ProtectHome=true
    PrivateTmp=true  PrivateDevices=true  ProtectKernelTunables=true
    ProtectKernelModules=true  ProtectControlGroups=true
    RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX
    RestrictNamespaces=true  LockPersonality=true
    ReadWritePaths=/opt/probe/data

  systemctl daemon-reload && systemctl enable --now probe-server

  → 首次启动自动生成管理令牌 /opt/probe/data/admin.token（0600）

【步骤 5】注册节点（管理 API）
  TOKEN=$(cat /opt/probe/data/admin.token)
  curl -s -X POST http://127.0.0.1:19080/api/admin/nodes \
    -H "X-Admin-Token: $TOKEN" -H "Content-Type: application/json" \
    -d '{"name":"hostdzire-印度","provider":"hostdzire","region":"印度",
         "group":"prod","note":"Probe 验证环境","expireAt":"","price":0,"currency":"USD"}'

  返回：
    {"id":"n_58b470b92be2", ..., "token":"6fe772f3…（48 字符）"}

  → 令牌由服务端生成（24 字节随机），不接受客户端指定

【步骤 6】安装被控端
  /etc/probe/agent.json（0640 root:probe）
    {
      "server": "http://127.0.0.1:19080",
      "nodeId": "n_58b470b92be2",
      "token": "<48位令牌>",
      "interval": 30
    }

  /etc/systemd/system/probe-agent.service
    User=probe  Group=probe
    ExecStart=/usr/local/bin/probe-agent -config /etc/probe/agent.json
    Restart=always
    （同样启用全套 systemd 沙箱选项）

  systemctl daemon-reload && systemctl enable --now probe-agent

【步骤 7】验证
  systemctl is-active probe-server probe-agent   → active / active
  ss -lntp | grep 19080                          → 127.0.0.1:19080 监听
  curl -s http://127.0.0.1:19080/healthz         → ok
  curl -s http://127.0.0.1:19080/api/nodes       → 节点在线

五、部署过程中发现并修复的缺陷（重要）
--------------------------------------------------------------------------------

  【现象】
    首次部署完成后一切正常（14:28:25、14:28:55、14:29:25、14:29:55 均上报成功）。
    但在测试 6「重启恢复」时重启了 probe-server，随后 Agent 日志变为：
        14:30:25  上报被拒绝: HTTP 401
        14:30:55  上报被拒绝: HTTP 401
        …… 此后每 30 秒持续 401，节点在面板上变红（离线）

  【根因】
    model.Node.Token 的 JSON 标签为 `json:"-"`，目的是防止上报令牌
    通过公开 API 泄露给前端。副作用是：**令牌也不会被写入 state.json**。
    服务端启动时从快照恢复节点，Token 字段为空，
    于是 NodeByToken() 的 `n.Token != token` 恒为真 → 全部上报被判 401。

    这是一个只有"重启"才会暴露的缺陷 —— 首次部署、连续上报、
    内存中运行全部正常，因此极易漏测。

  【影响面】
    所有 Agent 在服务端每次重启后都会永久失联，直到手动重发令牌。
    对生产环境属于致命问题。

  【修复】
    在快照结构中增加独立的 tokens 字段，与节点信息分开持久化：

        type snapshot struct {
            Nodes  map[string]*model.Node  `json:"nodes"`
            ...
            Tokens map[string]string       `json:"tokens"`  // 令牌单独持久化
        }

    保存时从节点提取令牌写入 tokens；加载时回填到 Node.Token。
    Node.Token 仍保持 `json:"-"`，公开 API 依旧不会泄露令牌。

  【回归测试】
    新增 internal/store/store_test.go，含 4 个用例：
      · TestTokenPersistsAcrossRestart   —— 重启后令牌必须保留且可通过校验
      · TestTokenNotLeakedToStateFile    —— 令牌只出现在 tokens 字段
      · TestRingWrapsAndKeepsOrder       —— 环形缓冲环绕后顺序正确
      · TestRingDedupSameSecond          —— 同一秒重复上报去重
    go test ./... → ok  github.com/motao/probe/internal/store

  【修复后验证】
    替换二进制 → 重启服务端 → 重新签发令牌 → 重启 Agent
      → 上报恢复：AGE=6s  ONLINE=True  曲线点数=4
    强制快照落盘后检查：
      state.json 含 tokens 字段: True | 节点数: 1 | 令牌数: 1
    再次重启服务端（关键验证点）：
      → AGE=2s  ONLINE=True  曲线点数=5
      → Agent 日志无 401，恢复 30 秒稳定上报
    结论：令牌持久化修复生效，重启不再导致 Agent 失联。


六、面板环境适配方式
--------------------------------------------------------------------------------
  本机未安装面板，故按"原生 systemd"部署。以下为面板环境的对接方式，
  设计上已针对面板场景做了取舍：

  【兼容性设计】
    · 不依赖 Docker —— 避免与面板的容器管理、端口映射冲突
    · 文件放 /opt/probe + /usr/local/bin —— 不侵入 /www/server（宝塔）
      或 /opt/1panel（1Panel）的受管目录
    · 端口选 19080 —— 避开宝塔 888/8888、1Panel 7870/8090 等常用端口
    · 服务名 probe-server / probe-agent —— 不与面板服务重名
    · 仅监听 127.0.0.1 —— 天然适配面板反向代理模式

  【宝塔面板（BT Panel）】
    1. 网站 → 添加站点（填写域名，无需 PHP/数据库）
    2. 站点设置 → 反向代理 → 添加反向代理
         代理名称: probe
         目标 URL: http://127.0.0.1:19080
         发送域名: $host
    3. 如需访问控制，可在"站点设置 → 访问限制"启用 Basic Auth
    4. SSL 可在"站点设置 → SSL"一键申请 Let's Encrypt

  【1Panel】
    1. 网站 → 创建网站 → 选择"反向代理"类型
         主域名: probe.example.com
         代理地址: http://127.0.0.1:19080
    2. 网站 → 配置 → HTTPS 开启证书（1Panel 自动续期）
    3. 如需 Basic Auth，在 1Panel 的"网站 → 配置文件"中加入：
         auth_basic "Probe";
         auth_basic_user_file /opt/1panel/apps/openresty/conf/htpasswd;

  【也可以用内置 Basic Auth，无需面板介入】
    修改 probe-server.service 的 ExecStart，追加：
        -auth admin:<强密码> -addr 0.0.0.0:19080
    然后放行端口。这样即使直接暴露公网也有访问控制。

  【面板环境下的备份建议】
    把 /opt/probe/data 加入面板的定期备份任务（宝塔"计划任务 →
    备份目录"，1Panel"计划任务 → 备份目录"）。
    数据仅几十 KB，备份成本可忽略。
